# 深度案卷（Deep Dossier）：多卷调研报告标准作业法

> 一句话：把"写一份五万字级的研究报告"从灵感活，变成一条可复现的流水线——先拷问、再采集、后拍板、逐卷交付。
> 适用体量：多卷、万字级以上、需要外部检索与一手材料、可能跨多个会话完成。
> 本技能只管"项目怎么跑"，不管"写什么内容"——内容规则（文风、术语、政治纪律）按你自己的标准来。

## 〇、When to Use（触发门）

**用**：要做"深度调研报告／全景报告／分析案卷／长白皮书"，且满足任一——
① 多卷 ② 万字级以上 ③ 需要外部检索与一手材料 ④ 可能跨 session ⑤ 要长期归档

**不用**：几千字的轻量问答、速查、即兴查证、不需要归档的小题目。

**判断口诀**：能不能一句话说完结论？能 → 走轻量流程；不能 → 上本技能。

## 一、配方总览（十二项基本功＋四项选配）

| # | 环节 | 机制 |
| --- | --- | --- |
| 1 | 起手 | 八枝拷问树（见第二节），产出《收网总结》表 |
| 2 | 采集 | 语义搜索分波入库；**结果只落文件不进上下文**；时间线随搜随建 |
| 3 | 底账 | `资料/` 目录 + 附件二写"检索底账"（件数/分组/与卷对应） |
| 4 | 骨架 | 先出《总纲》→ **委托方拍板才动笔** |
| 5 | 结构 | **一问一卷**（核心问题意识驱动）＋卷首元数据块 |
| 6 | 节奏 | 逐卷落盘 → 200 字导读 → **等验收再进下一卷** |
| 7 | 证据 | 原文引录规矩＋数据硬尺＋来源分层（见第五节） |
| 8 | 立场 | 主次矛盾分列＋责任分账＋历史纵深暗线＋"可惜"式落点＋N 问收尾 |
| 9 | 敏感 | 四条通用防火墙＋完整版底稿/降敏版接口 |
| 10 | 自审 | `scripts/selfcheck.py` 机器自查（必跑） |
| 11 | 附件 | 时间线大事记＋数据看板与来源矩阵 |
| 12 | 归档 | 目录模板（索引/总纲/分卷/附件/资料）＋版本记录表 |

**四项选配**（本技能默认全开）：
- a. 卷内固定收口："本卷小结"＋"下一卷"衔接，读者不迷路
- b. 导读固定模板（字数／主线编号／验收要点）
- c. "核心五问"启发式：为什么是这里、为什么是此时 → 那只手怎么伸进来 → 谁在推方向盘 → 凭什么骗到人、又怎么把人用掉 → 谁失职、谁获利、然后呢
- d. 篇幅校准：每卷 0.8-1.5 万字、全案 5-6 万字；某卷偏薄时**补新事实（补料批）而不抒情填空**

## 二、起手：八枝拷问树（必做，全盘清才动笔）

长篇报告是项目级任务，**先拷问后动手**。

| # | 枝 | 盘什么 |
| --- | --- | --- |
| 1 | 时间跨度 | 长时段（前史→高潮→现状）还是聚焦单事件；跨度过长时，对照事件嵌专节还是独立成卷 |
| 2 | 定性骨架 | 主要矛盾／根源矛盾／各方责任口径——报告的"灵魂"，篇幅分配跟着它走 |
| 3 | 叙事基调与落点 | 冷峻＋"可惜"式收束；0 感叹号；结尾落"N 问" |
| 4 | 核心问题意识 | 报告必须回答的 N 问，列清单请委托方确认/增删；可给"专节 vs 独立成卷"选项 |
| 5 | 结构 | 分几卷、卷名、附件（时间线/数据矩阵）、篇幅量级 |
| 6 | 来源分层 | 每层来源的使用规则；要不要原始文献引录 |
| 7 | 敏感线 | 完整版 vs 降敏版；四条防火墙的具体内容 |
| 8 | 执行细则 | 模型与通道、落盘路径、节奏；委托方答"篇幅你定"＝授权你定 |

**拷问规矩**：一次只问一问；每题带 A/B/C/D 选项＋推荐＋后果；委托方常只回一个字母，编号要能秒选；遇到需要单独拍板的新料（如"要不要把 X 也写进去"）单独成问，别混进别的枝。
**收网**：全盘问完，先出《收网总结》表格（已确认决定／被改掉的决定／开放问题／风险两条），再开工。

## 三、采集：分波入库（省 token 的命门）

```bash
# 语义搜索：query 写"理想页面的自然语言描述"，不是关键词
<搜索工具> --query "<理想页面描述>" --num 5 --output text > 资料/01_主题.md
# 只回显标题速览，正文留在文件里
grep -m3 '^Title:' 资料/01_主题.md
# 写作时按需抽事实与数字（不要全文精读）
grep -ohE '.{0,80}(关键词).{0,120}' 资料/0*.md | head -20
```

- 一次调用连跑 4-6 条，各自重定向落盘；编号按主题排（事件线／结构病灶／外部力量／组织与人群／清算／对比／历史与信息战）
- 写某卷前，针对该卷缺口再补 2-3 条（补料批），编号续排
- 时间线随搜随建，不最后补；命中官方文件（会议记录、统计报告、法院文书、法律原文）优先入库
- 归档时在附件二写"检索底账"：件数、分组、与卷对应、可复核

## 四、骨架与写作：总纲拍板门 → 一问一卷

**建目录**：`<项目根>/<主题>_<YYYYMMDD>/`，下设 `分卷/`、`资料/`。

**总纲**（模板：`templates/00-total-outline.md`）：总定性一句 ＋ 每卷论点骨架（每卷 3-6 条）＋ 关键待查项 ＋ 结构/附件/篇幅/纪律清单 ＋ 已入库资料清单 → **交委托方过目、拍板前不动正文**。

**逐卷写**：
- 卷 = 一个核心问题；卷内小节按论证链排（现状 → 机制 → 实证 → 判断）
- 卷首元数据块：所属报告／本卷回答／生成模型／数据截至／分析立场（模板：`templates/volume.md`）
- 卷末固定收口：本卷小结（3-4 条编号）＋"下一卷：《X》——一句话"
- 每卷完成 → 跑自查 → 落盘 → 发导读（模板：`templates/volume-teaser.md`：路径＋字数＋主线编号＋验收要点＋下一步）→ **等验收纠错，再进下一卷**

## 五、证据规矩

**原文引录（该贴就贴）**：法律条文、判词、庭审证词、通信原文、记者问答、宣言与历史文献——**照贴原文＋标注出处**；转述的必须标来源。转述会同时丢掉温度和证据力；唯一例外是口号类（见第七节）。

**数据硬尺**：官方统计为骨、≥2 个独立源为肉；规模类数字（人数/场次/金额）**双口径并列**（主办方称 X／官方称 Y）；宁少引，不引虚数；数据一律进附件二矩阵。

**来源分层与使用规则**：

| 层 | 来源 | 使用方式 |
| --- | --- | --- |
| 1 一手官方 | 会议记录与答问、政府统计、法院文书、法律与条约原文 | 直接引用，标文号日期 |
| 2 官方媒体 | 官方通讯社与党媒 | 事实可用；关键数据交叉一源 |
| 3 立场鲜明的本地媒体 | 事件当事地的私营/独立媒体 | **批判使用**：只取事实拼图，不采其定性用语 |
| 4 外部国家媒体与机构 | 外部大国媒体、NGO 与智库简报 | **作证据与靶子**：引其报道证明外部角色；不作定性依据 |
| 5 立场相近的评论 | 与你立场同源的学者/评论者 | 分析框架优先采信 |
| 6 学术 | 期刊论文、学位论文、智库报告 | 结构与机制分析，标注作者与刊物 |

## 六、立场参数（默认：左翼唯物史观；可替换）

见 `references/stance-framework.md`。默认骨架：

1. **三段式**：外部操盘者是纵火者、本地阶级结构是干柴、流行意识形态是助燃剂
2. **主次矛盾分列**：主要矛盾（事件性质）与根源矛盾（结构病灶）分开写，不混为一谈
3. **责任分账**：外部力量／本地代理／治理方／资本——各归各账；不洗地任何一方，也拒绝各打五十大板（结构性施暴与自卫反抗要分清）
4. **历史纵深暗线**：在更长的时间尺度里找"可惜"的根据（本可走上另一条路，那条路被切断/遗忘了）
5. **收束**："可惜非可恶"＋"N 问"收尾，把全书收成一把
6. **纪律**：称谓严谨；禁用神学/救世主色彩词汇与抽象煽情词；历史原话保真、不私自加感叹号

> 立场可替换：换成你自己的立场框架时，只需重写 `references/stance-framework.md`，其余流程不变。

## 七、敏感线（四条通用防火墙＋降敏版接口）

1. 口号类：正文一律**转述描述、标注性质**，不直接引用原文（报告不该成为传播载体）
2. 不与本地政治禁忌事件做类比，也不擦边
3. 在任高层政治人物：只引公开文件与官方表述，不做直接评点（**下级官员、机构、资本的责任批评照写**）
4. 争议事件：走"证据链 → 官方澄清 → 谣言如何被量产"的解剖路数，不单独做事实认定

**版本策略**：完整版写足为底稿；需要给他人传阅时，另抽降敏版（删精确数字与最敏感段落）。**先写足再删，不先阉着写。**

> 以上四条是**默认建议**，不是不可改的教条——请按你自己的传播环境与风险承受度调整（许可允许修改）。

## 八、收尾：附件双件＋索引＋归档

- `附件_时间线大事记.md`：大纵深报告**必配**，按年月日编年、分期成表（模板：`templates/attachment-timeline.md`）
- `附件_数据看板与来源矩阵.md`：关键数据＋来源＋可信度分级＋检索底账（模板：`templates/attachment-databoard.md`）
- `00_卷目录索引.md`：目录、阅读顺序建议、纪律清单、版本记录（模板：`templates/00-index.md`）

## 九、机器自审（每卷必跑，全案收尾必跑）

```bash
python scripts/selfcheck.py "分卷/*.md" "附件_*.md" "00_*.md"
```

检查项：感叹号数（必须 0，引文也不得私自加）、树状/连线字符（必须 0）、**代码块里包表格**（必须 0；代码块里放命令行是允许的）、头部"生成模型／数据截至"字段、字数与表格统计。退出码非 0 = 有文件不合格，不得交付。

> 报告文件用默认参数；检查技能/说明类文档时加 `--no-header`（那类文件没有"生成模型"字段）。

## 十、执行环境建议

- **单线程推进**：不要并发派发多个子代理（多数反代/网关环境会限流报错）；用待办清单分阶段跑
- **材料进文件，不进上下文**：每卷写完即落盘，进度靠文件而不是记忆
- **头部标注生成模型**（如 `deepseek-v4-flash`／`gemini-3.8-flash-high`），供版本回溯与质感审计
- **去私人化**：正式报告里不出现委托方的私人信息、本机路径、联系方式

## 十一、行为守则与反模式

**守则**：事实优先于立场；每个关键数字可溯源；引文一字不改；把"事实"与"分析"分开标注；核实不了的材料宁可删掉；结论给出推论链，让读者自己走完最后一步。

| 反模式 | 该怎么做 |
| --- | --- |
| 一上来就写正文 | 先拷问八枝，出《收网总结》 |
| 把搜索结果全文读进上下文 | 落盘 + grep 抽事实 |
| 总纲没拍板就动笔 | 设"拍板门"，拍板前只做采集 |
| 一次交付五万字 | 逐卷落盘 + 导读 + 验收 |
| 用形容词代替证据 | 一手文件原文上台 |
| 数字只引一处 | 双源交叉 + 双口径并列 |
| 用树状字符画结构图 | 原生 Markdown 表格 |
| 情绪化修辞、感叹号满天飞 | 0 感叹号，让读者自己得结论 |
| 混入委托方私人信息 | 去私人化硬隔离 |
| 并发派发子代理赶进度 | 单线程分阶段推进 |
